RNLCore

A managed cellular failover router for small businesses. When the ISP drops, card terminals, POS and Wi-Fi keep running on cellular, with no one touching anything.

Designed, built and operated end to end by Ryan Donahue, founder of RNLCore LLC. Hardware, firmware, cloud backend, customer portal, billing and go-to-market.

The problem

An hour offline costs a small shop more than a year of backup service

Restaurants, salons and auto dealers run payments, online orders and scheduling through the cloud. When the ISP goes down, card readers stop, delivery apps stop taking orders, and staff stand around while the owner sits on hold. The 2024 CDK Global outage, which knocked dealership software offline nationwide, showed how exposed this market is.

Enterprise failover gear exists (Cradlepoint, Peplink), but it is priced and configured for IT departments. RNLCore's goal was the same protection as a box a shop owner plugs in, with the cellular service, monitoring and billing managed for them.

What I built

Four layers, one product

The router sits between the ISP modem and everything in the business. A control plane in the cloud knows the state of every device, decides whether cellular service is allowed, and feeds a customer dashboard and an internal admin console.

Normal: traffic on ISP Outage: automatic switch to cellular, then back Management and data

Edge device

GL.iNet GL-X3000 with a 5G modem, re-flashed with a patched OpenWrt image. Becomes the shop's router: LAN ports for wired equipment, Wi-Fi for everything else, both protected.

Cellular service

Soracom multi-carrier SIMs, so a unit uses whichever major network is strongest at the site. Tuned to idle cheaply and only spend data during an outage.

Control plane

Python/FastAPI backend and the single source of truth for every device. On each check-in it returns the policy the router must obey. Billing state maps directly to network access, through Stripe webhooks and an entitlement state machine.

Customer + operations

RNL Hub, a React/Vite dashboard showing online status, normal vs. backup mode, usage and invoices, with Stripe checkout. A separate admin console for accounts, provisioned devices and notes.

Engineering log

Problems I hit on real hardware, and how I solved them

ArchitectureAuthority off-device

Designed the system so routers are stateless enforcers and all authority lives in the control plane. Devices enforce, the control plane decides, the UIs only reflect state. No customer or UI action can override it.

Every check-in returns a versioned policy the device must apply exactly:

allowed · allow_wired · allow_cellular · captive_portal
policy_version · message · checkin_interval_seconds · fail_closed

Lock rules are non-negotiable: an unknown device, a reboot or power loss, a factory reset, or an unreachable control plane all mean locked until the backend explicitly re-authorizes.

ProvisioningZero-trust identity

Each unit gets a canonical UUIDv4 generated off-device and written to /etc/rnl/identity.json. The device can never create, change or self-register its own ID. An admin registers that exact ID as inventory, still locked, and only assigning it to a paying account can unlock it.

Customers then claim their unit by serial number in RNL Hub. Claims are idempotent, and duplicate or already-assigned serials are rejected with a controlled conflict.

OperationsAudited admin

The admin console (RNLConnect) covers the device registry, assign, unassign and reassign between accounts, time-boxed temporary unlocks, and device replacement. Every admin action goes to an immutable audit log, and support roles are deliberately restricted.

Backend built with Alembic migrations (including hashed tokens) and a pytest suite, and validated against a device simulator before hardware integration.

Idle data cost~94% lower

Units on standby were burning metered cellular data. I traced it to the vendor multi-WAN daemon (kmwan) pinging over cellular every 3 seconds to check health.

Retuned the check interval to 35 seconds, which kept outage detection fast enough for a shop while cutting idle SIM cost by about 94%.

Service enforcementFail-closed

Designed the service lock so an unpaid or unreachable device can't run up cellular charges. rnl-checkin reports to the control plane; if it can't confirm service, rnl-lock installs an iptables/ip6tables FORWARD chain that blocks cellular forwarding while leaving the wired ISP path untouched.

The customer's normal internet never breaks because of billing. Only the backup path is gated.

ReliabilitySelf-healing

Built a modem watchdog with an escalation ladder. When the WAN drops it retries the modem in stages, and if the modem stays unresponsive after three attempts it raises an alert to the control plane.

RNL_CORE: WAN down - modem watchdog activating
RNL_CORE: Heal L4: modem unresponsive after 3 attempts - alerting Control Plane
Latency under load316 → 22 ms

Bench-tested the cellular path and found loaded latency spiking to 666 ms. After configuration changes, the extra latency under load dropped from about 316 ms to about 22 ms, which matters for card terminals and VoIP during an outage.

Also found the carrier's public IP breaking out in Oregon for a New Jersey unit, which explains the baseline latency and is a carrier-path tradeoff to weigh.

Root causeIPv6 on the SIM

Chased a client-specific streaming failure through the system log to the SIM rejecting IPv6 data calls in a 60-second retry loop (QMI error on requestSetupDataCall). Disabling IPv6 on the cellular interface let the IPv4 bearer dial cleanly in about 20 seconds.

DeploymentGolden Base

Packaged every patch into a repeatable build kit: a base image, an overlay, a patched modem script and network/modem configs, staged by build_golden_base.sh. Any stock X3000 becomes an RNLCore unit the same way every time.

Product and go-to-market

Packaged for owners, not IT departments

Setup is one cable from the ISP modem, power, and a registration code. I designed two service models and a launch offer around how small businesses actually buy.

Flex

Customer owns the hardware and turns backup service on when they want it. Lower commitment, pay for protection as needed.

Guard

Hardware and always-on backup bundled into one monthly payment. Set it and forget it.
